## 1. 專案結構

```
.
├── database/                      資料庫 DDL + 種子資料 + 建置腳本（唯一權威來源）
│   ├── 縣市區域檔.sql              DDL: sys_county, sys_district
│   ├── cms_homepage_service.sql   DDL: cms_homepage_service_vendor, cms_homepage_service
│   ├── account_and_label.sql      DDL: label, service_label, vendor_accounts, user_accounts
│   ├── 諮詢單相關table.sql        DDL: pms_form 系列
│   ├── mms_order_record.sql       DDL: mms_order_record
│   ├── mms_order_review.sql       DDL: mms_order_review

│   ├── 縣市區域範例資料.json       Seed

│   ├── 諮詢單相關範例資料.json     Seed
│   ├── order_record範例資料.json  Seed（.csv 為同內容備用格式）
│   └── import_seed_data.py       一鍵建表 + 匯入種子資料工具
├── api_server/                    FastAPI DB Access API Server
│   ├── requirements.txt
│   ├── .env.example               環境變數範本（.env 本身已 gitignore）
│   ├── app/
│   │   ├── main.py                應用程式入口
│   │   ├── config.py              環境變數設定
│   │   ├── database.py            SQLAlchemy engine/session
│   │   ├── models.py               ORM models（映射既有 schema）
│   │   ├── schemas.py              Pydantic Create/Update/Out
│   │   ├── security.py             密碼雜湊（bcrypt）
│   │   ├── crypto.py               PII 欄位 AES-256-GCM 加解密
│   │   ├── utils.py                分頁、UUID v7 等共用工具
```

**檔案權威原則**：資料庫相關檔案（DDL、種子資料、建置腳本）一律以 `database/` 內版本為準,不應在其他位置放置重複副本,避免修正遺漏同步造成不一致。

## 2. 技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 資料庫 | PostgreSQL 16 | 既有 DDL 大量使用 `jsonb`/`bytea`/`uuid`/`serial4`/`timestamptz` 等 PostgreSQL 專屬語法,且 AWS RDS 有直接對應的 RDS for PostgreSQL,遷移不需換方言 |
| API 框架 | FastAPI + uvicorn | 自動產生 OpenAPI 文件（`/docs`）、Pydantic 型別驗證、效能良好 |
| ORM | SQLAlchemy 2.0（同步模式） | 對應既有 schema 做映射,不負責建表（避免與 `database/` 建置流程衝突） |
| 密碼雜湊 | bcrypt | 不可逆雜湊,符合 schema 註解要求 |
| PII 加密 | cryptography（AES-256-GCM） | 對應 `contact_name`/`member_phone` 等 bytea 欄位的加密需求 |

## 3. 本地建置：資料庫

### 3.1 啟動本地 PostgreSQL（Docker）

```powershell
docker run --name aiwave-pg -d `
  -e POSTGRES_PASSWORD=<你的密碼> `
  -e POSTGRES_DB=aiwave `
  -p 5432:5432 `
  postgres:16
```

不用 Docker 也可以，只要有能連線的 PostgreSQL 15/16 執行個體即可（本機安裝、既有測試伺服器皆可）。

### 3.2 安裝 Python 相依套件

```powershell
pip install psycopg2-binary
```

### 3.3 執行建置腳本

```powershell
$env:PGHOST="localhost"
$env:PGPORT="5432"
$env:PGDATABASE="aiwave"
$env:PGUSER="postgres"
$env:PGPASSWORD="<你的密碼>"
$env:PGSSLMODE="disable"
python database\import_seed_data.py
```

腳本執行順序（對應 README.pdf 建議寫入順序 + 缺口補建）：

```
Step 1 — 建表
  縣市區域檔.sql → cms_homepage_service.sql → account_and_label.sql
  → 諮詢單相關table.sql → mms_order_record.sql → mms_order_review.sql
  → mms_review_summary.sql

Step 2 — 匯入主檔種子資料
  縣市區域範例資料.json → 相關主檔設定.json
  → 帳號與標籤範例資料.json → 諮詢單相關範例資料.json
```

```powershell
docker exec aiwave-pg psql -U postgres -d aiwave -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
```

⚠️ `DROP SCHEMA CASCADE` 會清除該資料庫下所有資料表，僅適用於測試資料庫，正式環境**絕對不要**執行這個指令。

## 4. 本地部署：API Server

### 4.1 安裝相依套件

```powershell
cd api_server
pip install -r requirements.txt
```

### 4.2 設定環境變數

複製 `.env.example` 為 `.env`，填入第 3 章建立的資料庫連線資訊：

```
PG_HOST=localhost
PG_PORT=5432
PG_DBNAME=aiwave
PG_USER=postgres
PG_PASSWORD=<你的密碼>
PG_SSLMODE=disable
```

其他可選設定：
- `PII_ENCRYPTION_KEY_B64`：PII 欄位加密金鑰（base64 編碼的 32 bytes）。未設定時加密欄位一律回傳 `null`，只有 `_hash` 欄位可用（見第 8 章）。
- `CORS_ALLOW_ORIGINS`：預設 `*`（開發用），正式環境請改白名單。

### 4.3 啟動伺服器

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`--reload` 僅供本地開發使用（程式碼變更自動重啟），正式環境部署請移除此參數（見第 7 章）。

### 4.4 確認啟動成功

開啟 http://127.0.0.1:8000/docs 應能看到 Swagger UI，列出全部 94 個端點。或用指令檢查：

```powershell
curl http://127.0.0.1:8000/health
# 預期回應: {"status":"ok"}
```

## 5. 整合驗證

建議至少手動驗證以下 3 條關鍵流程，確保資料庫與 API server 正確串接：

1. **登入流程**：`POST /auth/user/login`（帳號用 `database/帳號與標籤範例資料.json` 內既有的 `user01@example.com`，密碼 `Test@1234`），應回傳 `inbr_account_id`。
2. **查看訂單拼接邏輯**：`GET /users/{inbr_account_id}/order-summary`，應回傳 `feedbacks` 與 `orders` 兩個陣列。
3. **表單結構讀取**：`GET /forms/9/full`，應回傳完整的 group + topic + option + media 結構。

完整端點清單與型別說明見 `API_Reference.md`。

## 6. 已知問題與修正紀錄

1. **`mms_order_record.sql` 語法錯誤（已修正）**：原始檔案 `order_status` 欄位的多行註解字串缺少結尾單引號與分號，導致該檔案在任何 PostgreSQL 環境下都會建表失敗（後續 SQL 語句會被誤判為同一個未結束的字串）。已補上正確結尾，內容文字未變動。
2. **serial/bigserial 主鍵序列未同步（已修正）**：`label`、`pms_form`、`pms_form_group`、`pms_form_topic`、`pms_topic_media`、`pms_topic_option`、`mms_order_record` 這 7 張表用 `serial4`/`bigserial` 主鍵，但種子資料用**明確指定 id 值**寫入。PostgreSQL 遇到顯式 id INSERT 不會自動同步內部序列，導致之後透過 API 新增資料（不帶 id，交由序列自動產生）時可能撞上既有種子資料 id，報 `UniqueViolation`。已在 `import_seed_data.py` 新增 Step 4（用 `setval` 校正序列），此問題是在實測 `POST /labels` 端點時發現的。
3. **JSONB 欄位型別過窄（已修正）**：API 層 Pydantic schema 原將 `order_items`/`vendor_data`/`feedback_content`/`feature` 這些 JSONB 欄位寫死成 `dict`，但既有種子資料裡 `order_items` 有些記錄實際是 list 格式，導致驗證失敗。已改用 `dict | list` 聯合型別放寬限制。

## 7. 遷移至 AWS

本節說明如何將本地驗證過的架構搬到 AWS，分為「資料庫遷移」與「API server 部署」兩部分。

### 7.1 資料庫遷移到 RDS for PostgreSQL

#### 步驟 1：建立 RDS 執行個體

在 AWS Console（或用 `aws rds create-db-instance` CLI）建立：
- 引擎：**PostgreSQL 16**（與本地驗證版本一致，避免版本差異造成的行為不一致）
- 執行個體規格：依預期流量選擇，測試/小流量可用 `db.t3.micro` 或 `db.t4g.micro`
- 儲存空間：預設 GP3，依資料量調整
- **不要**勾選「公開存取」（Publicly Accessible）——除非有明確理由需要從公網連線,否則應限制在 VPC 內網存取

#### 步驟 2：設定安全群組（Security Group）

RDS 的安全群組**只允許**你的 API server 所在的安全群組/子網段連入 5432 埠，絕對不要對 `0.0.0.0/0` 開放：

```
Inbound Rule:
  Type: PostgreSQL
  Port: 5432
  Source: <API server 的安全群組 ID>（不是 0.0.0.0/0）
```

#### 步驟 3：執行建置腳本，指向 RDS

RDS 建立完成後會取得一個 endpoint（例如 `aiwave-db.xxxxxxxxxx.ap-northeast-1.rds.amazonaws.com`）。從你的 VPC 內（例如一台跳板機 EC2，或未來要部署 API server 的那台機器）執行：

```powershell
$env:PGHOST="aiwave-db.xxxxxxxxxx.ap-northeast-1.rds.amazonaws.com"
$env:PGPORT="5432"
$env:PGDATABASE="aiwave"
$env:PGUSER="postgres"
$env:PGPASSWORD="<RDS主帳號密碼>"
$env:PGSSLMODE="require"   # ← 連線 RDS 務必用 require，本地測試才用 disable
python database\import_seed_data.py
```

⚠️ `import_seed_data.py` 是**一次性建置工具**，只適合初始化。正式環境上線後的日常資料寫入應該全部透過 API server（`app/routers/`），不要對正式 RDS 重複執行這個腳本（`CREATE TABLE` 遇到已存在的表會直接失敗）。

#### 步驟 4：密碼管理

不要把 RDS 密碼寫死在程式碼、命令列參數或版本控制裡。建議：
- 開發/測試：環境變數（如上）
- 正式環境：**AWS Secrets Manager** 或 **AWS Systems Manager Parameter Store**，讓 API server 啟動時動態讀取，而不是寫在 `.env` 檔案裡

### 7.2 API Server 部署方式比較

| 方案 | 優點 | 缺點 | 適合情境 |
|---|---|---|---|
| **EC2** | 掌控度最高，設定最直覺，成本可預測 | 需自行處理系統更新、擴縮容、健康檢查 | 想直接掌控伺服器、預算固定的小型部署 |
| **ECS Fargate** | 免管理伺服器，容器化部署，可設定自動擴縮容 | 需寫 Dockerfile + 熟悉 ECS 概念，學習曲線較高 | 中長期會迭代、需要彈性擴縮容的正式環境 |
| **App Runner** | 最簡單，直接從程式碼或容器映像一鍵部署，自動處理負載平衡/擴縮容/HTTPS | 客製化程度較低，成本在高流量時可能較不透明 | 想快速上線、團隊沒有太多 DevOps 資源 |

黑客松/demo 階段推薦 **App Runner**（設定最少、最快看到成果）；若確定要長期營運且需要更多基礎設施控制，再考慮 ECS Fargate。以下以 App Runner 為主要示範，EC2 作為備選簡述。

#### 方案 A：AWS App Runner（推薦，最快上線）

1. 為 `api_server/` 新增 `Dockerfile`：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app/ ./app/
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

2. 建置並推送映像至 **Amazon ECR**：

```powershell
aws ecr create-repository --repository-name aiwave-api-server
docker build -t aiwave-api-server ./api_server
docker tag aiwave-api-server:latest <你的AWS帳號ID>.dkr.ecr.<region>.amazonaws.com/aiwave-api-server:latest
aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin <你的AWS帳號ID>.dkr.ecr.<region>.amazonaws.com
docker push <你的AWS帳號ID>.dkr.ecr.<region>.amazonaws.com/aiwave-api-server:latest
```

3. 在 App Runner 建立服務，來源選擇剛推送的 ECR 映像，設定環境變數（`PG_HOST`、`PG_PORT`、`PG_DBNAME`、`PG_USER`、`PG_PASSWORD` 建議改用 Secrets Manager 參照、`PG_SSLMODE=require`）。
4. 設定 App Runner 的 VPC connector，讓它能連進 RDS 所在的 VPC（否則會連不到私有子網內的資料庫）。
5. 部署完成後 App Runner 會提供一個 HTTPS URL，即可直接使用，不需要額外設定 SSL 證書。

#### 方案 B：EC2（掌控度較高）

1. 啟動一台 EC2（Amazon Linux 2023 或 Ubuntu），安全群組只開放 443/80（若前面掛負載平衡器）或限制來源的 22（SSH 管理用）。
2. 安裝 Python、pip，`git clone` 或上傳 `api_server/`。
3. 安裝相依套件、設定 `.env`（或改用 systemd 環境變數）。
4. 用 **systemd** 讓服務常駐（而不是直接跑 `uvicorn`，重開機/當機需要自動重啟）：

```ini
# /etc/systemd/system/aiwave-api.service
[Unit]
Description=AIWave DB Access API
After=network.target

[Service]
User=ec2-user
WorkingDirectory=/home/ec2-user/api_server
ExecStart=/usr/bin/python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable aiwave-api
sudo systemctl start aiwave-api
```

5. 建議在前面掛一個 **Application Load Balancer**（處理 HTTPS 終止/證書、健康檢查），不要讓 uvicorn 直接對外裸奔在 80/443。

### 7.3 網路架構建議

```
Internet
   │
   ▼
[ALB / App Runner 自動配置的端點]  ← HTTPS 終止於此
   │
   ▼
[API Server (EC2 / ECS Fargate / App Runner)]  ← 私有子網或受控環境
   │
   ▼
[RDS for PostgreSQL]  ← 私有子網，安全群組只允許 API server 連入
```

- API server 與 RDS 應盡量放在同一個 VPC 的私有子網，只透過安全群組（不是對外 IP）互相溝通。
- RDS 不開放公網存取；若真的需要從本機直接連 RDS 做維運（如跑遷移腳本），透過 **VPN**、**Bastion Host（跳板機）** 或 **AWS Systems Manager Session Manager** 連線，而不是暫時對 `0.0.0.0/0` 開洞。

### 7.4 環境變數對照表（本地 → AWS）

| 變數 | 本地值 | AWS 正式環境建議 |
|---|---|---|
| `PG_HOST` | `localhost` | RDS endpoint |
| `PG_SSLMODE` | `disable` | `require` |
| `PG_PASSWORD` | 明文寫在 `.env` | 從 Secrets Manager 動態注入，不落地檔案 |
| `PII_ENCRYPTION_KEY_B64` | 可留空（停用加密） | 必須設定，金鑰存在 Secrets Manager / KMS |
| `CORS_ALLOW_ORIGINS` | `*` | 改為實際前端網域白名單 |

## 8. 上線前安全檢查清單

目前 API server **沒有任何身分驗證機制**，這是為了先專注在資料存取層功能而刻意暫緩的部分。正式對外上線前，以下項目必須處理：

- [ ] **加上身分驗證**：`/auth/*/login` 目前只做帳密核對後回傳識別碼，未簽發 JWT/Session token，任何知道 `inbr_account_id`/`service_vendor_id` 的人都能呼叫其他端點存取該身分資料。需加上 Token 機制，並在各業務端點檢查呼叫者權限。
- [ ] **CORS 改白名單**：`CORS_ALLOW_ORIGINS=*` 僅適合開發，正式環境改成實際前端網域。
- [ ] **設定 PII 加密金鑰**：`PII_ENCRYPTION_KEY_B64` 未設定時所有加密欄位回傳 `null`，正式環境要有真實個資落地務必設定，並將金鑰存在 AWS Secrets Manager 或 KMS，不要寫在環境變數明文檔案。
- [ ] **RDS 安全群組收斂**：只允許 API server 所在安全群組連入，不對公網開放。
- [ ] **移除 `--reload`**：正式環境的 uvicorn 啟動指令不應帶 `--reload`（效能較差且僅供開發用）。
- [ ] **啟用 HTTPS**：透過 ALB 或 App Runner 自動配置的 HTTPS，不要讓 API 明文裸奔在 HTTP。
- [ ] **審視管理端 CRUD 的操作者追蹤**：目前無登入驗證時，`cre_id`/`upd_id` 暫填系統識別碼（`app/utils.py` 的 `SYSTEM_ACTOR_ID`），加上身分驗證後應改用實際登入者 id。

其餘設計限制（軟刪除範圍、複合主鍵刪除方式、無實體 FK 約束等）詳見 `api_server/README.md`。
